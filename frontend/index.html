ContractIQ documentation

ContractIQ checks whether an API response follows its expected contract using JSON Schema validation.

How validation works

  1. Enter an API endpoint and choose its HTTP method.
  2. Provide a JSON Schema describing the expected response.
  3. Run the validation and inspect the PASS or FAIL result.
  4. Review errors to identify missing fields, incorrect data types, or request errors.

Validation history

Validation attempts are stored in a local SQLite database. The Dashboard displays total validations, successful validations, failed validations and the pass rate. The History page displays saved validation records.

Demo scenarios

  • Valid response: checks a response against the contract.
  • Wrong data type: demonstrates a type mismatch.
  • Missing field: demonstrates a missing required property.
  • Unexpected status code: demonstrates a simulated request failure.
